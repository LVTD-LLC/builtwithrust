## Document workflow discovery — verified 2026-10-22

[Inlyne](https://github.com/Inlyne-Project/inlyne#features) views Markdown with limited HTML support and refreshes on file writes; it is not a general browser and does not aim to support forms or every CSS style. [Typst's compiler repository](https://github.com/typst/typst#readme) contains the Rust compiler and CLI for local typesetting; the collaborative online editor is a separate product surface. The [Typst tutorial](https://typst.app/docs/tutorial/) covers document authoring and PDF output. Do not imply these are interchangeable editors, that Markdown/LaTeX source transfers unchanged, or that we performed a rendering benchmark. The existing Productivity category owns the output-first chooser and reversible acceptance checklist; recommend only currently published category listings. Its dated WebPageElement does not change earlier guides' dates or invent a combined catalog lastmod.

## JavaScript workflow discovery — verified 2026-10-21

[Biome](https://biomejs.dev/introduction/comparison-with-other-tools/) provides source linting and formatting; rule coverage and formatting can differ from an existing setup. [Rspack](https://www.rspack.dev/guide/migration/webpack) targets webpack-oriented application builds; compatibility must be checked per loader/plugin and version. Its [SWC loader](https://www.rspack.dev/guide/languages/typescript) transforms TypeScript without type checking. [Turbopack](https://nextjs.org/docs/app/api-reference/turbopack) is a Rust bundler integrated into Next.js, not a linter; it does not itself type-check and webpack configuration is not a drop-in equivalent. Preserve the framework/CI type-check path and test it explicitly. The category owns a short chooser/checklist, not a tested migration or benchmark; recommend only currently published listings in the category. Existing titles, URLs, star snapshots and older guide dates remain unchanged.

## Data workflow discovery — verified 2026-10-16

qsv is a command-line toolkit for tabular data; available commands depend on its build/features (https://github.com/dathere/qsv#installation). Its optional `sqlp` command uses Polars, so do not frame qsv and Polars as entirely separate competing engines (https://github.com/dathere/qsv/blob/master/docs/help/sqlp.md). Polars provides DataFrame expressions and lazy queries in Python and Rust (https://docs.pola.rs/user-guide/getting-started/ and https://docs.pola.rs/user-guide/lazy/using/). The Data & AI category owns a short workflow chooser; the existing Python-tools guide owns Polars's place alongside uv and Ruff. No benchmark advantage, universal build support or hands-on results are claimed.

## Fish and its editor tooling — verified 2026-10-14

Fish 4.0 ported the shell implementation from C++ to Rust, not every repository asset: its own retrospective describes Fish scripts, Python tools and remaining C. Source: https://fishshell.com/blog/rustport/ . fish-lsp is a separate TypeScript language server for Fish scripts (https://www.fish-lsp.dev/docs/how-it-works); rust-analyzer serves Rust source code (https://rust-analyzer.github.io/). Implementation language does not determine which language server edits a file. The Fish listing owns this short distinction; do not create a duplicate Fish LSP article or label fish-lsp as Rust-built.

## Networking task scope — verified 2026-10-18

Official references: [gping](https://github.com/orf/gping) graphs ping times for multiple hosts; [Trippy](https://trippy.rs/) combines traceroute and ping, with platform-specific privilege requirements; [Sniffnet](https://github.com/GyulyVGC/sniffnet) inspects traffic and imports/exports PCAP captures, with platform-specific capture dependencies; [Pingora](https://github.com/cloudflare/pingora) is a Rust framework for programmable network services and HTTP proxies. Do not treat these tools as interchangeable application-health tests or claim a measured performance winner. The infrastructure chooser links only to currently published projects in that category.

## File-sharing task scope — verified 2026-10-19

[miniserve](https://github.com/svenstaro/miniserve#usage) v0.35.0 supports authentication, optional browser uploads and read-only WebDAV (PROPFIND). [Dufs](https://github.com/sigoden/dufs#access-control) v0.47.0 supports path-scoped account rules and writable operations bounded by global permissions; an account rw rule alone does not enable uploads. Both serve files and offer browser uploads/authentication. Do not say miniserve lacks WebDAV or imply a successful browser upload proves WebDAV writes work. The category owns the short chooser/checklist, not a security audit or backup/sync comparison. Loopback fixture checks do not establish remote/TLS or cross-platform client compatibility. Preserve original project URLs, titles and star snapshots.
